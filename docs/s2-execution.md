# S2 自动学习记忆

2026-10-07。开发验证覆盖本地 JVM、现有 Android 模拟器和真实模型；Mate 50 留在 S6 交付验收。

## 存储与来源

Room 29→30 非破坏性自动迁移新增 `learning_memory_state(profile_id PRIMARY KEY, payload)`。payload 为 MemoryState（schemaVersion=1）。背景、偏好、进度、卡点/错因、表现、复习事项分别采用 BACKGROUND/PREFERENCE/PROGRESS/DIFFICULTY/PERFORMANCE/REVIEW_SUGGESTION。READ_ONLY/WITH_HINT/INDEPENDENT_ATTEMPT 等证据分级不等于掌握度；候选、冲突、失效条目不作为事实检索。

本期按档案聚合来源、条目、修订、抑制和 Job，用一个 Room 事务原子提交。数据合同 v1 的表是逻辑设计，本期没有逐张建表；也没有复用上游按助手保存的 MemoryEntity。原始消息留在 MessageNode/UIMessage，来源只保存应用签发 UUID、会话/节点/消息 ID、版本、完整用户文本的 code point 范围和按档案 HMAC 摘要。模型回答、附件正文和教材作者不作为本人事实来源。

来源还保留上游原消息的本地时间；上游没有记录时区，不能伪造 UTC 精度。抽取与检索明确说明相对时间属于原消息日期，不将旧聊天中的“明年/本周”重新解释为抽取当天。条目创建、更新、Job 和租约仍用 UTC Unix 毫秒。

会话新增、编辑、删除和用户消息分支切换与来源失效共用事务。Job 固定原始档案，提交重新检查任务状态/尝试次数、来源、删除 epoch、人工 revision、最新开关及候选 allowlist。人工编辑采用 revision 比较更新并保存历史；自动冲突进入 DISPUTED，人工修订保持优先。

## 抽取与准确反馈

记忆页首次启用说明额外模型请求、本地存储、已有已完成聊天补处理与关闭方式。开关用专用原子更新，避免通用 update() 保留旧档案字段。完成聊天后入队，启动补处理未成功消费的来源。成功 Job 的来源集合和 rangeHash 充当游标；失败不消费，零候选是成功但不反馈保存了记忆。

每批最多 8 条来源，每条最多 4000 UTF-16 单元，超过预算整批失败，不截断后假装完整抽取。响应最多 48000 字符、20 候选、每条 2000 code points。严格拒绝未知字段、重复 JSON key、重复事实键、空证据、伪造来源、错误枚举及明显凭据。最多三次尝试，90 秒请求超时、180 秒租约、30/60 秒重试间隔；租约过期恢复，终态失败可人工重试。有聊天正在生成时不启动新抽取。

本轮以记住/请记住/重新记住开头时提供 save_explicit_memory。档案、会话和消息由运行层绑定，正文必须逐字来自本轮消息，真正提交才返回 saved=true。显式手工保存不依赖“使用记忆”开关；关闭时仍可按本轮明确请求保存，但不会读取或注入已有记忆。系统规则禁止没有保存工具成功结果时声称已保存。普通抽取不会自行解除删除抑制。

## 更正、删除和跨会话检索

页面支持搜索、原始来源、返回聊天、编辑确认、修订历史、删除单条、忘记主题、抽取状态和重试。按 profile 重建页面状态与订阅，切换不沿用另一人的列表、数量和弹窗。

旧助手/全局记忆的页面仅提供前往主记忆入口的说明，不再加载或修改无学习者归属的旧表；助手列表不显示旧共享记忆数量。旧数据未擅自分配给当前人，新模型请求只使用有档案和来源的新记忆。

删除清除条目及修订正文，用 Keystore HMAC 保留最小消息/事实/主题抑制键，递增 epoch 并撤销在途抽取。消息约束覆盖旧消息全部编辑版本及保留相同消息 ID 的分支。原聊天供本人回看，后续模型上下文排除抑制消息及对应回答；存在删除来源时保守禁用模型历史搜索工具，避免 FTS 摘录绕过删除。只有新明确用户消息能重新记住。保护密钥缺失时停止自动处理，不能新建密钥绕过旧删除约束。

检索只取本档案 ACTIVE 且有有效来源的条目：最多 8 条、正文合计 3600 字符、最终 JSON 最多 4800 字符，每条最多携带 3 个来源 ID。支持线代/线性代数、求导/导数、特征根/特征值等固定别名。模型背景携带时间、证据和 origin，人工修订优先、记忆不是指令、不表示正式掌握度。页面显示最近请求选用的记录。没有另存画像摘要或正文检索缓存。

“使用记忆”开关同时控制自动抽取和聊天中使用已有记忆。关闭后，新请求按会话所属档案跳过检索，不更新选用记录；生成入口再次检查该档案开关，不向流式或非流式请求注入已有学习记忆/旧助手记忆。未找到所属档案时也不注入，不能以当前选中档案的开关代替会话归属。已有条目保留供本人查看、编辑或删除；重新开启恢复正常检索。删除来源的消息/回答过滤及历史搜索工具禁用始终生效，与使用开关无关。旧全局记忆读写工具继续禁用，不扩大聊天历史引用开关的语义。

## 验证与范围

运行 scripts/test_s2_completion.ps1：app/ai/search JVM、APK、记忆数据库与页面、S1 回归，独立 seed→force-stop→verify 重启。加 -RealModel 使用模拟器既有加密连接，核验 30 组预先标注来源、新会话检索和真实保存工具，不读取或输出密钥。最终证据位于 qa/s2。

2026-10-10 请求语义回归位于 `FlutterChatBridgeTest.memoryToggleGatesCapturedRequestsAndReenableRestoresRetrieval` 和 `generationBoundaryUsesConversationProfileAndKeepsDeletionFiltering`，本轮均在模拟器通过：使用真实桥接/ChatService/GenerationLoop 与本地 HTTP 提供商，实际捕获流式及非流式请求，覆盖关闭不检索/不注入、重新开启、会话与当前档案开关相反、档案缺失、删除过滤及显式保存工具仍可用。没有调用真实外部模型；已有独立进程记忆持久化测试因未提供 seed 夹具而跳过，不计入本轮通过项。

本期面向本机一至两名学习者；聚合存储没有宣称无限历史规模。后台任务在应用进程中运行，进程重开续接，不保证被系统终止期间执行。已经发给模型的数据不能假装撤回。HMAC 跨设备迁移与加密备份合并在 S5 验证，Mate 50 在 S6 验证。
