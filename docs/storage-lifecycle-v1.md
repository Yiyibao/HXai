# 开发存储生命周期 v1

来源：2026-11-03 用户要求“增加约束，完善统一回收机制，杜绝文件占用泛滥”。原始 Pro 包保留不变。本机制管理开发临时文件，不修改 App 任务、授权、模型、数据库协议。

## 占用限制

唯一配置 `.hxai-storage-policy.json`：工作树12 GiB、所有已登记工作树合计16 GiB、生成目录8 GiB、一次性运行6 GiB，磁盘保留10 GiB。最多2个工作树、1个活动运行、1批保留输出；保留不超过24小时。默认一次性输出结束即清，最多32条紧凑回执，单次日志8 MiB。提交文件16 MiB，日志256 KiB；生成二进制、工具链、数据库不能直接提交，精确源码夹具例外需有据可查。

`report` 不删除文件；`check` 在开工和提交前阻断超限。统计所有 Git 已登记工作树（含当前根目录内 .git），按逻辑文件大小计费，不跟随链接并报告跳过路径；不等于磁盘簇占用或全机盘点。构建 wrapper 与四个现有主要验证入口已调用预检。未接线的历史入口也须通过统一 `run`。本地 pre-commit hook 每次克隆安装一次；不覆盖用户已有 hooksPath/hook。

## 登记和回收

`run --feature ID --kind test|build|visual --disposable -- COMMAND` 创建唯一 `.local/hxai-runs/<随机ID>`，子进程取得 `HXAI_RUN_DIR`、`HXAI_QA_OUTPUT` 及 TMP/TEMP/TMPDIR。调用方必须主动使用这些目录；任意硬编码输出不会被自动改写，也不会被自动认领。`--preserve` 明确保留且绝不自动删除；受保留批次数约束，须人工确认后处理，不能当自动 GC 使用。

注册表位于 Git common dir 的 `hxai-storage/registry.json`，所有关联工作树共用系统文件锁。记录绑定仓库、工作树、随机ID与nonce，路径不可由调用方任意指定。状态为 ACTIVE → CLOSED → GC_PENDING → CLEANED；异常或进程状态不明为 BLOCKED。只有明确 disposable、已结束、到期且无活跃写入进程的记录能进入回收。中断不按时间自动放行，不自动杀进程或重新派发。

删除前核对路径边界、marker、Git 跟踪状态、无链接/junction/嵌套Git，先保存 GC_PENDING，再改名为同父目录 `.gc-<ID>`，删除后独立检查原路径和隔离路径均不存在。删除中途失败保留意图，后续 `gc --apply` 可恢复同一隔离目录；原目录与隔离目录同时存在、记录损坏、标记不符或身份未知均阻断。不提供任意路径注册、force、reset 或按时间猜测死任务的入口。

`gc` 默认预览。未知旧 build/QA/SDK、真实运行数据库、凭据、用户材料、原始规范、Git元数据仅统计，绝不纳入自动删除。发生 BLOCKED 时先检查 `report`、目录与进程，再人工结算；不可抹去注册表以绕过。

## 构建与证据

Gradle使用 `--no-daemon`；仅前台、无后台存活子任务的本地测试使用一次性输出。可用 `-I scripts/storage.init.gradle` 显式重定向原生模块 build；Flutter host AAR 保持单一复用仓库。SDK/Flutter/Gradle安装在项目外共享位置，AVD在外部共享池（规则最多两台、默认无快照）。脚本检测常见项目内工具链/AVD复制；外部缓存和设备池不在自动清理范围，须另行盘点，不能把迁出目录冒充全机回收。

日志记录完整输出流的SHA256、字节数、退出码、是否截断；不持久化命令参数明文（可能含密钥）。截断日志不冒充完整原始证据；验收需要的紧凑结果/失败反例应在回收前提取到本批审查目录。该目录不应保存整套临时产物或原始材料副本。超限即使子命令返回0，也不能报告存储通过；失败命令仍保留失败退出码并回收其明确一次性输出。

这不是内核实时配额：预检和结束检查之间仍可能短时超限，人为绕过入口、守护进程或外部工具缓存不能被该脚本完全拦截。若需要操作系统强制上限，下一步是独立受限磁盘/容器及进程树隔离，不通过虚构完成来替代。
