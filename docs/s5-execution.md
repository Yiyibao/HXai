# 加密备份与长期可靠性（2026-10-07）

本轮按用户要求实施“完整加密备份与恢复”和“长期使用可靠性”。这里的完成范围是客户端开发、故障注入和模拟器验证；Mate 50、连续真实使用观察和发布签名仍属于交付门禁。

## 备份与恢复

设置 → 备份 → 创建完整加密备份。输入并重复至少 12 字符的独立密码，选择系统文件保存位置。备份文件后缀为 `.msab`；仅在保存流成功关闭后更新最近备份时间。建议保留不同日期的两份副本。密码不保存，忘记密码无法恢复。

备份覆盖全部学习档案及当前选择、会话及分支（含置顶和归档状态）、持久化输入队列、学习记忆/来源/修订/删除抑制、材料和成果原文件与元数据、图片创作任务及父子版本关系、个人图片模板、上传附件、Skills 和字体。数据库使用 `VACUUM INTO` 一致性快照，材料成功记录必须与归档文件大小和 SHA-256 匹配；成功图片任务必须引用同档案的有效 PNG 成果。图片任务和模板的路径、记录 ID 与档案归属不一致时拒绝归档或恢复。处理中发生变化或成功文件缺失时拒绝备份，不能把不完整文件标记为成功。

API 密钥、请求头、接口连接配置、文档服务凭据、设备内凭据引用、临时解析缓存和执行环境不属于可移植学习数据。恢复后须重新配置连接。旧明文云备份、部分恢复接口及不可达的 WebDAV/S3 备份页面已移除；旧明文 ZIP 不自动当成新版完整备份导入。

格式 v1：16 字节随机盐、PBKDF2-HMAC-SHA256 / 600,000 次 / 256 位密钥；AES-256-GCM / 128 位认证标签；每块最多 256 KiB。每个归档生成 8 字节随机 nonce 前缀，追加 4 字节递增块号作为 96 位 nonce；44 字节固定头作为每块 AAD，包含明文总长度，拒绝截断、追加和块交换。恢复必须验证所有块、EOF、清单及 SHA-256 后才进入 staging。总明文上限 8 GiB、单条目 2 GiB、最多 100,000 条目，清单最多 8 MiB。使用平台 JCA 原语，没有自实现密码算法；分块避免 GCM 解密提供者缓冲整个大归档。原语依据 [NIST GCM 规范](https://csrc.nist.gov/pubs/sp/800/38/d/final)。

恢复流程：输入密码 → 选择文件 → 验证密码、清单、路径、材料、SQLite 完整性和 Room 版本 → 展示快照日期、档案和条目数 → 用户确认 → 持久化 pending → 退出并重新打开应用。安装在 Room/Koin/后台消费者初始化之前执行；档案列表、记忆开关与当前档案在同一次设置事务中替换，普通设置更新仍保留专用档案操作维护的状态。文件替换有原件、持久化日志、内容校验和回滚。取消或验证失败不改变当前学习数据。完整恢复会清理受管理文件夹中的快照外文件，包括 `image_creation` 和 `image_templates`，回滚时也恢复这些文件。附件 URL 随安装路径重定位，只处理 URL 字段，保留用户正文。

旧 `.msab` 仍按原清单校验和恢复；以前未归档的图片任务、版本关系及个人模板无法从 PNG 原件凭空重建。恢复旧快照不会保留目标安装上快照之外的这些记录。

恢复同一保护域的旧快照会在确认时及真正安装前再次合并当前删除规则，防止确认之后发生的删除被旧快照覆盖；较新的人工修订优先。快照中已完成任务不会重放，未完成抽取撤销，可人工重试；聊天输入队列沿用原有暂停恢复机制。不同记忆保护域不能合并到已有记忆库，须在空白安装中进行完整恢复；不会将陌生档案自动混入当前学习者。新设备只能知道快照内的删除约束，无法知道其他设备后来发生的删除。

## 记忆保护迁移

新版 HMAC 使用可导出的 256 位随机密钥：本机由 Android Keystore 凭据仓储保护，归档内由备份密码保护，接收设备重新保护。缺失或解密失败时保留原数据并停止处理，不生成替代密钥绕过现有删除约束。

旧版 Keystore HMAC 密钥不可导出。升级时校验并迁移仍可读取的消息版本及来源删除指纹；旧事实/主题删除指纹没有保留原始值，不能精确重算。此类旧档案保留记录和删除约束，并暂停自动抽取，页面明确提示使用新学习档案继续自动记忆；已有记忆仍可查看、编辑和删除。没有旧删除约束的档案可继续使用。该限制不是无损的密码原语迁移，不能声称所有旧档案自动抽取均保持可用。

## 长期使用

- 记忆任务保留 Room 租约、有限重试和幂等提交。取消时先在不可取消的清理段落盘失败状态，超时作为可重试失败，不吞掉真正的协程取消。
- 每个学习档案按设备本地日期每天最多 20 次自动抽取请求，失败也计入；达到上限保留任务，次日继续。每次最多 8 条来源、每条最多 4,000 字符，模型请求超时 90 秒。
- 最多保留 200 条终态任务明细，完成来源标识单独保留，避免压缩后重新抽取；会话最近使用记忆映射限制为 500 项。原始聊天和有证据的记忆来源不因任务压缩被删除。
- 唯一 WorkManager 周期任务在网络连接且电量不低时维护记忆，指数退避；前台继续短周期检查，后台不进行该短周期模型扫描。系统仍决定后台实际执行时机，强制停止后须用户重新打开。调度设计依据 [Android 持久后台任务文档](https://developer.android.com/develop/background-work/background-tasks/persistent)。
- 材料/成果元数据使用原子替换和 `fsync`，原文件落盘同步后原子移动，再登记成功；启动清理残留 `.part`/`.tmp` 并恢复中断状态。JSON 数据文件与元数据分别保存为 `.json` / `.meta.json`，修复旧版 JSON 输入覆盖冲突；已被旧版覆盖的 JSON 要重新上传，不能伪称恢复了原文件。
- 启动清理上次进程遗留的备份临时文件。迁移仍禁止 destructive fallback；凭据保护、聊天中断、队列暂停、档案隔离和分支保全继续沿用既有实现并进行回归。
