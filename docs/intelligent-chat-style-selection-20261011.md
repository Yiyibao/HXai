# 智能 Chat 未达标项与样式采集提示词

日期：2026-10-11（Asia/Taipei）。依据：`intelligent-chat-display-feedback-20261011.md` 中保存的用户审核反馈。该记录归档于 10 月 11 日，未单独记载每项审核发生时间。

用户已提供六张参考图并确认采用，对应实现和验证见 `chat-style-implementation-20261011.md`。下列提示词保留为样式采集记录。以下提示词用于收集实际展示参考，不要求 ChatGPT 输出本项目组件协议或 JSON。参考产品可能根据账号和工具能力采用不同展示；若某种原生组件不支持，应明确说明，不能用代码或静态图冒充实际交互。

## 1. 正文与卡片（UI-01，第 3 项）

未达标：正文和卡片区别太小，卡片不明显。

```text
我要选择 AI 聊天中的信息卡片样式。请先用普通正文展示“今天学习25分钟，完成8道题，下一步复习二次函数”，再用清晰的信息卡片展示相同内容，让我直接对比。
卡片要有明确边界、适度背景、标题层级和留白，整体简洁，适合手机阅读。请直接展示你当前支持的实际效果，不要输出 JSON 或网页源代码。若无法在聊天中直接显示卡片，请说明，并提供可打开的预览。
```

选择时看：容器是否明显、背景是否柔和、标题是否清楚，以及是否仍像聊天中的内容。

## 2. 方案比较（UI-02，第 7 项）

未达标：标题与内容区别不明显，各方案缺少明确边界。

```text
请比较三个通勤方案：步行30分钟、0元；骑车12分钟、2元；公交20分钟、3元。分别列出时间、费用、优点、缺点和适用情况，最后给出一条建议。
我主要想选择“方案比较”的展示样式。请直接展示三个标题醒目、边界清楚、字段对齐的方案块，适合手机纵向阅读；信息不要在正文和方案块中重复。不要输出 JSON 或网页源代码；若当前无法直接展示，请提供可打开的预览。
```

选择时看：每个方案的起止边界、标题层级、相同字段能否方便比较。

## 3. One Dark 代码块（UI-03，第 8 项及普通聊天代码）

未达标：代码展示效果不满意；用户明确指定 VS Code 的 One Dark 风格。

```text
请展示一段 Python 示例：定义计算平均数的函数，包含中文注释、字符串、数字、条件判断和一次函数调用。
我要查看聊天代码块的展示效果，请使用 Python 代码块，保留语言标题和当前支持的复制操作。视觉目标是 VS Code One Dark：深色代码背景、清晰的语法配色、等宽字体和舒适行距。不要输出 JSON。若聊天原生代码块不能切换 One Dark 主题，请明确说明，并另外提供可打开的 One Dark 预览，不要把原生默认主题称为 One Dark。
```

选择时看：代码区域与工具栏、语法颜色、字体大小、长行滚动；本项目浅色聊天也应使用已指定的深色代码块。

## 4. 图表坐标与样式（UI-04，第 10–12 项）

未达标：折线图不够美观，横纵坐标似乎未显示；柱状图、散点图也需检查。具体原因尚未确认。

先问折线图：

```text
请直接绘制一张简洁清晰的折线图：周一到周五的学习时长分别为20、35、25、45、30分钟。横轴为“日期”，纵轴为“学习时长（分钟）”，显示完整刻度、坐标轴、数据点及浅色网格。
我想选择聊天中的图表样式，请优先使用当前支持的图表展示，让我看到实际效果；配色克制、适合手机、坐标标签不能被裁切。不要仅给代码或 JSON。说明这个图是否支持查看数据点和放大。
```

再问柱状图：

```text
请沿用刚才的图表风格，把同一组学习时长改为柱状图。保留完整横纵轴、刻度和“分钟”单位，显示每根柱子的数值。请直接展示实际图表，不要仅给代码或 JSON。
```

再问散点图：

```text
请沿用刚才的图表风格绘制散点图。横轴“学习时长（分钟）”，纵轴“正确率（%）”，数据点为(20,60)、(35,75)、(25,65)、(45,90)、(30,70)。显示完整坐标轴、刻度和单位，纵轴范围0到100。请直接展示实际图表，不要仅给代码或 JSON。
```

选择时看：坐标轴、刻度、标题、单位、留白、数据提示及放大效果。三种图分别选择，不能用折线图效果代替另外两项验收。

## 5. 可交互数学绘图（UI-05，第 16 项）

未达标：数学绘图直接失败；失败原因尚未采集。选样式后仍需单独修复真实绘图链路。

```text
请制作一个可直接操作的二次函数演示：y=a*x²，a的范围为-3到3，默认1，步长0.1；x显示范围为-5到5。
提供滑块、当前a值和随滑块变化而更新的函数图像。图上显示x轴、y轴、原点、刻度，以及当前函数表达式，滑块操作时坐标范围保持稳定，便于比较开口方向和宽窄。整体适合手机查看。
请展示或提供可打开的实际交互预览，不要只给代码、JSON或静态图片。如果当前环境不能提供滑块交互，请明确说明。
```

选择时看：滑块的位置、参数读数、函数公式、坐标系统、重置与全屏体验；验证a为-3、0、1、3时的效果。

## 6. 概览布局（UI-06，暂关联第 18 项）

未达标：概览页不满意，具体不满意的细节未记录。暂按“概览/明细”标签页及指标布局准备提示词，这一对应尚未由用户确认。

```text
请制作一个简洁的学习数据概览，包含“概览”和“明细”两个可切换标签。
演示数据：本周学习5天，总时长155分钟，完成40道题，正确率78%；每天学习时长为20、35、25、45、30分钟。
概览先展示一条关键结论，再展示分组清晰的核心指标和学习时长趋势；明细展示每日数据表。标题、指标名称、数字和补充说明要有清楚层级，避免堆砌相同大小的卡片，适合手机阅读。
请提供可打开、可切换标签的实际预览，不要只给 JSON 或源代码。若当前只能提供静态展示，请说明。
```

选择时看：首先看到什么、指标如何分组、图表和结论的关系、标签选中状态。

## 7. 修改成果与版本保留（UI-07，第 23 项）

未达标：点击“基于当前成果修改”后出现 JSON，疑似未正确展示修改成果；实际链路原因尚未确认。

在第 4 项图表或第 6 项概览所在聊天中继续问：

```text
请基于刚才的成果修改：将周五学习时长从30分钟改为50分钟，并更新相关图表、合计指标及结论。只修改受这条数据影响的部分。
请提供可以查看的新版成果，清楚标出版本或修改摘要，并保留能够查看的旧版。如果当前支持成果预览或版本切换，请使用这些实际操作入口。不要把工具参数、JSON或源代码当作最终成果展示；如果当前不支持旧版本访问，请明确说明。
```

选择时看：新版入口、修改摘要、旧版访问方式、版本标识；本项目后续还需验证修改工具调用与渲染，不能靠样式解决 JSON 外露问题。
