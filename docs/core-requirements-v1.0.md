# MathStudyAgent 核心需求总结 V1.0

整理日期：2026 年 10 月 9 日。来源：用户在本项目对话中提供的需求正文。本文件保存需求基线；技术建议见 [现状与重构方案](chat-first-refactor-assessment-20261009.md)。

项目定位：以 ChatGPT 手机端为主要参考的个人通用 AI 助手，具备可扩展的 Agent 能力。

## 一、产品定位

MathStudyAgent（MathAgent）并非专门面向数学学习的 Agent，而是一款以 ChatGPT 移动端为主要参考的通用 AI 助手。

- 主要目标：实现接近 ChatGPT 手机端的完整聊天体验，包括新推出的智能 Chat（动态交互式 UI）。
- 能力扩展：在聊天的基础上，强化文件处理、工具调用及 Skills 等能力。
- 使用场景：当前主要用于数学学习、日常问答和个人文件处理，但不应受到数学领域的限制。
- 目标用户：目前主要供开发者个人使用，未来可能开放给其他用户。

基本原则：Chat 是产品核心，Agent 是能力扩展。不为了体现 Agent 特性而增加不必要的复杂功能。

## 二、核心功能需求

### P0 — 完整的 ChatGPT 式聊天体验

这是 MathStudyAgent 最重要的功能，也是后续开发的首要方向。

- 自然流畅的多轮对话与上下文理解。
- 多模型接入与模型选择。
- 稳定的流式回答。
- Markdown、LaTeX、表格、代码块等富文本展示。
- 图片、附件及文件的输入和理解。
- 聊天历史与会话管理。
- 尽可能贴近 ChatGPT 手机端的交互体验。

具体功能完成度需要结合现有项目核实。

### P0 — 智能 Chat（Intelligent UI）

这是当前重点希望新增或完善的能力。让 AI 不局限于纯文本回答，而是根据用户的问题，自动生成合适的动态内容和可交互界面，例如：

- 交互式图表和数据展示。
- 参数滑块与实时计算。
- 动态卡片、表格和选择控件。
- 根据任务自动组织不同的内容布局。
- 用户可以操作组件，并在必要时继续与 AI 交互。

技术调研已涉及 Flutter GenUI、A2UI 及社区开源实现。目前它们只是候选技术路线，尚未确定最终选型。智能 Chat 应作为通用聊天能力，而不是数学专属功能；同时尽可能考虑不同模型的兼容性。

### P0 — 文件理解、处理与成果交付

目标是实现接近或优于 ChatGPT 手机端的实用文件处理体验。

- 上传、读取和理解文件。
- 对文档内容进行分析、总结与提取。
- 对真实文件进行修改、转换与处理。
- 生成 PDF、Word、Excel、PPT 等实际成果。
- 将处理后的文件交付给用户下载或继续使用。
- 在聊天中自然发起和完成文件任务。

现有基础：项目服务器已经部署了复杂文件处理能力。后续应重点核实这些现有能力，并将其融入 Chat 工作流，而不是重新建设一套重复的文件处理系统。这也是当前最有实际价值的 Agent 能力方向。

#### 文件工具自动调度（2026-10-09 用户确认补充）

用户上传文件并提出任务后，助手根据任务、文件类型和实际内容，自动选择本地读取、模型视觉理解、MinerU 增强解析或文件编辑/生成工具。用户不需要指定工具名称，也不需要每次明确要求 OCR 或 MinerU。

- 普通文本、可提取文字的 PDF 和 Office 文档优先使用对应读取工具；本地结果足以完成任务时不重复调用 MinerU。
- 图片问答可直接使用支持图片的模型；扫描 PDF、需要结构化提取的图片，或本地提取缺失且增强识别能够帮助完成任务时，按需自动调用已配置、启用的 MinerU 服务。
- 文件生成、修改与转换使用相应文件工具；只有任务依赖扫描材料的内容时，才先调用 MinerU 识别。MinerU 不承担 Word、Excel、PPT 等成果生成。
- 仅上传文件、尚未提出处理任务时，不默认启动整份文件的远端解析。按请求处理相关页或内容，优先复用有效的已解析结果。
- 自动调度融入聊天：显示实际处理状态，完成后继续原任务并交付真实成果；失败说明原因和可用范围，支持重试、取消。
- 服务配置与启用仍是使用前提；不要求每个任务再开启一次自动解析选项。未配置、停用或不可用时，使用可行替代方式或说明缺失条件，不伪造处理成功。用户当次要求“仅本地处理”或“不上传服务器”时遵循该限制。

这是已确认的新需求，取代旧方案中“必须明确请求增强解析，不能因本地提取不足自动上传”的限制。详细场景与验收需求见 [文件自动调度需求](file-auto-dispatch-requirements.md)。当前先梳理需求，不改代码；上述行为尚不能作为当前客户端已实现的能力。

### P1 — Skills 支持与完善

希望 MathStudyAgent 可以方便地使用社区现成的 Skills，例如 GitHub 上的文档处理、Office、数据分析和其他通用技能。

- Skills 功能据现有开发进展，已初步实现。
- 具体实现范围和兼容程度尚待检查。
- 后续重点是验证现有实现、完善社区 Skills 的接入和使用体验。

暂不需要直接规划大型 Skill 商店或复杂的插件生态。

### P2 — MCP 扩展支持

MCP 的主要价值，是未来可以更加方便地接入其他软件及第三方服务。

- 暂时不开发完整的 MCP 功能。
- 不把 MCP 作为当前核心任务。
- 架构上尽量避免阻断未来增加 MCP 支持的可能性。

## 三、现有项目状态

目前已确认：前端框架重构已由 Gemini 完成；当前技术栈涉及 Kotlin + Flutter；服务器端已经部署复杂文件处理能力；Skills 已有初步实现。

仍需在项目中核实：

- Kotlin 与 Flutter 的实际职责分工。
- 现有 Chat 功能的完成度。
- 聊天消息渲染与流式输出的实现情况。
- 智能 Chat 是否已有基础结构。
- 文件处理服务的接口与当前集成程度。
- Skills 的具体实现和社区兼容性。

不应在检查现有代码之前，直接认定这些功能需要重新开发。

## 四、当前暂不纳入核心需求的能力

- Codex 式完整编程 Agent。
- 远程控制个人电脑。
- 通用浏览器自动化。
- 多 Agent 协同系统。
- 大规模自动化任务平台。
- 完整的 MCP 生态系统。
- 面向商业化的大规模多用户管理系统。

不排除未来根据实际需求增加。

## 五、后续项目梳理重点

1. 现状核查：已经实现了什么，哪些功能只是初步可用？
2. Chat 体验对标：与 ChatGPT 手机端相比，主要缺少什么？
3. 智能 Chat 方案：如何让 Flutter 支持模型驱动的动态交互 UI？
4. 文件处理整合：如何充分利用已经部署的服务器能力？
5. Skills 检查：现有实现能否使用社区现成 Skills？
6. 扩展性评估：能否在不增加当前开发负担的前提下，为未来 MCP 等能力保留空间？

## 六、最终目标

MathStudyAgent 不是一个功能复杂但聊天体验普通的 Agent，也不是仅仅调用大模型 API 的简单聊天客户端。

它应当首先是一个好用、自然、完整、接近 ChatGPT 手机端体验的个人 AI 助手。

在此基础上，通过智能交互界面、强大的文件处理系统和可扩展的 Skills，让它拥有比普通聊天应用更大的能力空间。

开发方向：Chat-first，Agent-extend。

以上是当前需求基线，而非最终的技术实现方案。
