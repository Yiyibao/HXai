# MathStudyAgent 现状核查与 Chat-first 重构建议

日期：2026-10-09。依据：[用户需求 V1.0](core-requirements-v1.0.md)、项目记忆、当前工作区源码、历史执行证据与本次官方技术资料查询。

本轮完成需求与架构梳理，没有修改客户端、调用真实模型、重新运行 APK 或改变服务器。本报告中的源码缺口是静态核查结论；历史测试数字仅属于其对应批次。用户确认 Gemini 前端框架重构已完成，本文进一步区分框架接入和完整功能接通。

## 1. 结论与需求纠正

适合在现有 Flutter + Kotlin + 文档服务上渐进重构。主要工作是解除数学教学的强制约束、补齐 Flutter 对既有功能的接线、引入可持久化的交互消息，以及增强真实文件操作。模型 SDK、会话与工具执行、材料仓库、文档任务、凭据和备份均有可复用实现。

| 项目 | 历史设计 | V1.0 与建议 |
|---|---|---|
| 产品身份 | 数学师范学习 Agent | 个人通用 AI 助手；数学是使用场景 |
| 对话行为 | 强制教学模式、诊断练习复习闭环 | 默认直接满足用户意图；教学改为可选行为/Skill |
| Agent 价值 | 教学记忆、学习成果、教学闭环 | 围绕聊天完成真实文件任务，智能交互帮助理解与操作 |
| 页面结构 | 聊天/材料/记忆/成果同级 | 建议聊天主屏，历史侧栏，文件库次入口，记忆与 Skills 在设置/会话能力中 |
| 用户范围 | 一至两名数学学习者 | 先自用；保留已有数据隔离，为未来开放留基础 |
| MathStudy 分工 | 正式学习数据必须交给 MathStudy | MathStudy 变为可选关联应用，不限制通用聊天和文件成果 |
| 记忆 | 学习表现与学习卡点为主 | 保留历史数据和可靠性机制；通用记忆范围待明确，不能擅自删除或扩张抽取 |
| 智能 UI | 固定学习页面与少量工具显示 | 通用 P0，模型生成动态组件，用户操作可继续对话 |
| Skills/MCP | Skills 曾后置；MCP 禁用 | Skills P1；MCP P2，保留适配空间，无须为 UI 先建 MCP |

导航、命名和实现建议尚非用户最终选型。不要求现在改包名或移动整个源码目录。V1.0 未撤销既有自动记忆需求；保持可用和可控，避免把通用聊天自动转成学习评价。

## 2. 当前实际架构

```text
Flutter：界面、路由、Riverpod 状态、公式显示
    ↓ Pigeon 命令 / EventChannel（事件业务接线待补）
Kotlin：StudyHostFacade → ChatService / Repository / ProviderManager
    ├─ 会话与工具执行、Room、模型提供商 SDK
    ├─ LearningMemoryStore、MaterialFiles、CredentialVault、备份与诊断
    └─ DocumentServiceRepository → HTTPS 文档服务
服务器：FastAPI 网关 + SQLite 任务 + 调度器 + MinerU CPU Basic worker
```

- Flutter 模块在 `client/flutter_ui/`；正式启动入口为 `StudyFlutterActivity`；原 `RouteActivity` 保留外部 Intent/原生入口。
- `StudyHostFacade` 提供会话、记忆、材料、成果、模型和诊断等桥接。当前没有文档服务配置/任务与 Skills 管理桥接，也没有真实文件导入桥接。
- Kotlin 仍是主要业务系统；Compose 的旧页面、既有 Android 测试和工具渲染仍存在。切换主入口不会自动迁移这些页面的全部功能。
- 历史本地收尾见 [closure 报告](../qa/closure-20261008/report.md)：对应原生范围的会话、审批、Skills、附件与五格式交付有验证基础。
- [Flutter 交付报告](../qa/flutter-migration/report.md) 宣称 F0–F5 全通过，但下节源码与部分宣称不一致。不能直接将它当作当前新入口完整验收结论。

## 3. 按需求核查完成度

| 能力 | 已有基础 | 当前 Flutter 缺口 / 重构工作 |
|---|---|---|
| 多轮聊天与模型接入 | Kotlin 会话树、生成循环、多个 Provider | 补真实配置入口、错误传播、消息更新与模型选择校验 |
| 流式与停止恢复 | ChatService 有生成状态与会话流 | EventChannel 定义了，但本次查到只有切档事件发送，Flutter 无 eventStream 消费；发送后一次刷新不足以呈现后续流式 |
| Markdown/数学 | Flutter 已有公式组件；Kotlin 有成熟消息组件 | 当前 MathMarkdownView 主要解析公式并显示文本，无完整 Markdown 标题/表格/代码块解析，需补富文本渲染 |
| 图片/附件输入 | 原生选择器、私有材料库、解析与模型工具 | Flutter 附件按钮只弹“已就绪 SAF 文件选择器”；待选附件列表没有选择器填充路径 |
| 图片/文件消息 | DTO 可传图片/文档 URI | 图片走 Image.network，需正确处理本地 file/content URI；文件消息缺专用附件卡片 |
| 历史与会话管理 | Kotlin DAO/Repository 与分支 | 列表 provider 有，但聊天没有历史导航；仅拉50条，无完整搜索/分页/重命名/删除入口 |
| 动态智能 UI | Kotlin 有 chart_display、AskUser、JavaScript 工具，Compose 有专用渲染 | Flutter 没有 GenUI/A2UI 依赖、surface 状态或交互动作回传；工具输出被简化为文本，图表未接入 |
| 文件理解/生成 | MaterialTools 支持读取、分页、PDF页图、DOCX图片和五格式基础生成 | 通用 Chat 附件与任务、成果卡片未形成自然闭环 |
| 复杂解析 | DocumentServiceRepository、WorkManager、已部署 Basic worker | Flutter 无服务配置、指定页处理、任务进度/取消、块结果和原页核对入口 |
| 修改/转换真实文件 | 有基本读与新建文件工具 | 本次核查未见通用原件编辑/转换工具；重生成一个基础文件不能代表保留原排版的修改 |
| 成果交付 | 原生实际复制、重读校验、打开、分享 | Facade.saveArtifact 直接返回成功，无 SAF 保存；打开/分享需要复用已有校验和完整授权流程 |
| Skills | 安装/查看/启用/卸载、按需 use_skill、引用文件读取 | Flutter 无管理入口；加载说明文件不等于执行 Python/Node/Office 脚本 |
| 记忆 | 来源、版本、抽取、人工更正、删除抑制 | Facade 硬编码 evidenceType=QUOTE，sourceQuote/sourceConversationId=null，未传真实来源；抽取仍是学习专用 |
| 备份/诊断 | 密码备份、恢复回滚、脱敏诊断 | Flutter 只有简化诊断入口；备份与恢复未完整接线 |
| MCP | 上游 SDK 与相关源码保留 | ChatToolFactory 当前主动不暴露共享 MCP；按 V1.0 暂不开放 |

### 3.1 优先修正的实现不一致

1. **数学约束在生成核心强制注入。** `GenerationLoop.kt` 每次都加入 `studyMode.prompt` 与 `StudyLearningLoop.prompt`，包括自定义助手。应改成可选教学行为；仅改默认 systemPrompt 或选择“自由讨论”无法解决。
2. **教学枚举不一致。** Kotlin 为 GUIDED/HINT/CHECK/EXPLAIN；Flutter 为 GUIDED/SOCRATIC/EXAM/FREE，无法识别时默认 GUIDED；现有会话的模式选择还未调用持久化接口。通用重构应取消强制教学模式，并保留旧枚举迁移兼容。
3. **命令绕过业务入口。** 工具审批桥接直接改消息并 commitToolApproval；应复用 ChatService.handleToolApproval 等已验证路径，并验证续行、拒绝和重复提交。分支等操作也应统一走会话业务服务，避免数据库和活动 session 分离。
4. **身份与幂等合同不完整。** 请求带 epoch，但多处未校验；sendMessage 的幂等缓存仅在内存、未包含完整上下文且检查/执行非原子。保留已有档案隔离，在桥接边界完成所属验证与过期请求拒绝。
5. **错误与草稿。** 发送未等待成功就清空输入；部分 SimpleCommandResult 被调用者忽略；加载会话异常转成 null。需要保留失败草稿，明确可恢复错误，避免失败被当作空会话。
6. **交付证据范围。** Flutter 的32个数学测试主要检查 widget 挂载和 pump；无法证明完整 Markdown、公式内容正确或真实 Chat 链路。报告工具链部分与当前 Gradle 配置不一致，应重新采集实际版本和运行证据。

这些是下一阶段的具体修复输入，不是本轮新运行测试确认的结果。优先验证实际宿主源码与 APK 一致，避免拿旧原生包或不同构建的证据证明新 Flutter 入口。

## 4. 文件服务器应如何复用

当前仓库的服务器为 FastAPI + SQLite + MinerU 4.0.10 ONNX CPU Basic，已有部署与合成扫描件验证，见 [服务 README](../server/document-service/README.md) 与 [部署记录](document-service-execution.md)。本轮未访问生产服务，不确认此刻在线状态。

已记录能力是 PDF/图片指定页扫描解析，返回文本/公式/表格块、原物理页、来源图片及警告；每次最多5页、原文件最多30 MiB、单任务并行。Office 增强、服务端 Office 生成、复杂排版保真与精确 bbox 尚未交付。用户描述的“复杂文件处理”应细化为这些可验证能力，不能把 OCR 等同于通用文档编辑。

建议保留服务器和鉴权任务机制，追加能力而非重建网关：

1. Chat 选择附件 → Kotlin 导入私有材料库 → 聊天显示附件及可用范围。
2. 根据用户任务、文件类型和实际提取质量自动选择路径：普通内容优先本地/视觉读取，扫描件及必要的结构化提取按需自动调用已配置启用的 MinerU 服务，无需用户逐次指定工具。
3. 文档任务绑定 conversationId/messageId，上传/排队/解析/下载/完成分别显示真实状态。
4. 任务完成后读取校验结果，再由原会话继续总结、分析或生成成果；进程恢复时不重复提交和续行。
5. 成果直接以聊天文件卡片交付，支持预览、打开、另存、分享、继续修改；文件库保留统一检索与复用。
6. 真实编辑保存新版本，保留原件、源文件摘要及修改范围；新增转换工具明确输入/输出类型和格式损失。

2026-10-09 用户已确认采用自动调度。现有 parse_material_enhanced 工具仍要求明确请求增强解析，这是待实施时需调整的旧规则。新需求允许为用户文件任务按需调用已配置、启用的服务，不需要用户说出 MinerU/OCR，也不增加每任务必开的自动解析选项。生成文件本身不调用 MinerU；仅上传而没有任务时不默认解析全文；用户当次要求仅本地或不上传时遵循限制。具体需求与验收见 [文件自动调度需求](file-auto-dispatch-requirements.md)。本次仅更新需求，不改代码。

Office 执行能力可以增添独立 worker，共用现有身份、任务、下载校验接口。具体首批编辑需求应选真实样例，例如修改 Word 指定段落、清洗 Excel 并保留数值类型、PDF 合并/拆分，而不是先搭通用终端或大型工作流引擎。DOCX/XLSX/PPTX 的保真编辑、格式转换和新建文件分别验收。

## 5. 智能 Chat：建议的技术路线

### 5.1 当前查到的官方状态

- [Flutter 官方 GenUI 文档](https://docs.flutter.dev/ai/genui)：基于 JSON 和预定义 widget catalog 组合交互界面，官方仍标 experimental/alpha。
- [GenUI 官方仓库](https://github.com/flutter/genui)：框架与模型后端解耦，能够对接生成结构化 JSON 的模型；这不是任何模型在本项目都已验证兼容的保证。
- [官方接入说明](https://github.com/flutter/genui/blob/main/packages/genui/README.md)：可用自定义 AI 客户端向 transport adapter 提供响应。
- [A2UI 官方说明](https://a2ui.org/)：声明式 UI 协议，客户端用受控组件目录渲染。站点列 v0.9.1 current、v1.0 candidate；接入前需固定协议与实际 SDK/renderer 兼容版本，不能混用不同示例格式。

**GenUI 与 A2UI 可以配合使用。** 前者提供 Flutter 的渲染和交互设施，后者定义模型与客户端交换 UI 描述的协议。仅采用 GenUI 渲染层也不必引入多 Agent、MCP、A2A 服务器或把模型调用搬到 Dart。

### 5.2 推荐：保留模型业务层，原型验证 GenUI + A2UI

建议把 GenUI/A2UI 作为首选验证路线，而非直接定稿。Flutter 负责 catalog、surface 展示、本地组件状态；Kotlin 负责模型、工具、会话、身份、持久化与交互续行。

```text
用户问题 → Kotlin 模型/工具循环
    → 文字 / 文件 / 交互界面结构
    → 桥接校验与持久化 → Flutter 消息内 Surface
    → 本地控件变化，或“提交/继续分析”动作
    → Kotlin 校验当前会话与界面版本 → 同一对话继续
```

原型先用已有工具调用机制承载受控 UI 描述，也评估官方 transport adapter 直接解析文本流。完整结构校验前不能把半截 JSON 当成可执行动作；普通回答持续使用文本流。工具路径更容易沿用现有执行和存储，直接流式路径则需单独验证混合内容解析与协议错误恢复。

第一批组件建议：文本、卡片、表格、折线/柱形/散点图、滑块、输入框、选择器、按钮及有限布局。场景必须跨领域：预算对比、文件数据分析、数学函数参数探索。图表可复用旧 chart_display 的数据校验与工具语义，补 Flutter 渲染适配。

### 5.3 接入合同

- 新增版本化 InteractiveSurface 消息部分，包含 surfaceId、组件目录/协议版本、定义、数据状态、surfaceRevision、所属 messageId/branchId。
- surface 和用户动作与会话一起持久化；历史重开能渲染，重新生成或切换分支不会把动作送到错误版本。
- 统一事件 envelope 至少含会话/档案身份、epoch、序号及 revision；缺口重取快照，重复事件忽略。
- 滑块变化优先本地更新可验证计算，不每次拖动都请求模型；复杂计算调用受限计算工具，明确结果来源。提交动作再携带必要状态给模型。
- 组件交互只触发已登记 action，不运行模型生成的任意 Dart/HTML/JS，不允许 UI 自行扩权或访问凭据。第三方 SDK 的协议能力也不能替代应用身份与业务校验。
- 只有受信的模型输出/工具结果通道可以创建界面，普通附件正文中的 UI JSON 不自动执行。
- 支持能力分层：普通文本 → 结构化界面 → 工具交互。模型不支持或结构不合法时回退可读文本/静态表格，不能阻塞整个 Chat。
- 使用现有多个 Provider 实测结构输出和动作续行；原型至少两个不同提供商协议适配路径，真实模型需使用已有获授权配置。没有条件的项单列。

原型的选型标准：本项目 SDK 兼容、多模型成功率、桥接可控、重开恢复、组件可扩展、许可证和大字/无障碍表现。如果 alpha 依赖的集成成本过高，可暂用有限组件 renderer，但保持适配边界，避免直接另造庞大 UI 协议。

## 6. Skills 与未来 MCP

Skills 已有真基础：SkillManager、导入与路径/资源限制、原子安装、启用状态、use_skill 延迟读取正文和引用文件；此前关闭的是制作/编辑，并非安装和使用。启用目前属于 assistant 配置，导入文件为全局包；不能把新个人界面变成失去所属校验的共享执行入口。

| 社区技能类型 | 当前可用性 | 补齐方向 |
|---|---|---|
| 纯说明/提示词类 | 已有机制支持 | Flutter 导入、查看、启用、会话使用反馈 |
| 引用 Markdown 资料类 | 有相对路径读取支持 | 验证文件类型、编码、上下文预算和引用来源 |
| 依赖已有文件/计算工具类 | 可按工具适配 | 声明依赖并映射现有受限工具 |
| Python/Node/LibreOffice 脚本类 | 不能仅靠 use_skill 执行 | 受限服务端能力与依赖检查；先支持精选技能/任务 |
| 依赖桌面控制或专有插件类 | 当前不能承诺 | 显示缺失能力，暂缓 |

社区兼容需要逐技能验证其工具名、路径、依赖、模板与授权步骤。现有 JavaScript 计算工具和禁用的 workspace 不构成完整 Python/Office 执行环境。保留真实 Skill 指令与来源，通过适配满足其合理要求，不能删除步骤后仍宣称完全兼容。

MCP 留在能力适配层。保持 Tool 接口、执行结果与权限校验独立于 UI；未来增加 MCP adapter 即可。首批不建立统一插件商店、远端控制或多 Agent 平台。

## 7. 分阶段重构与验收

三个 P0 都进入本轮重构范围。下面是依赖顺序，智能 UI 原型可在 Chat 基础合同建立后与文件接线交错推进；不是将智能 Chat 无限后置。

| 批次 | 内容 | 可审查结果与完成条件 |
|---|---|---|
| R0 需求与基线 | V1.0 归档、旧限制标记、源码/APK/服务合同核对 | 明确保留/修改/暂缓表，记录对应构建；既有未提交改动不覆盖 |
| R1 通用 Chat + 桥接 | 解除强制教学；订阅、事件快照、身份和幂等；历史；富文本；模型配置；草稿；附件 | 真实连续对话、停止/失败重试/重开、选择文件与模型；已有会话/文件/记忆不丢失 |
| R2 智能 UI 原型与定稿 | GenUI/A2UI 版本固定、图表/表格/滑块/按钮、动作回传 | 三类跨领域场景；至少两条模型适配路径；历史恢复和非法结构回退；记录方案取舍 |
| R3 文件 Chat 闭环 | 复用原生导入与服务；任务消息；解析完成续聊；聊天成果卡片；另存/分享 | 上传扫描件→解析→分析→生成→实际打开/另存/分享；取消/断网/重复回调不伪造成功 |
| R4 智能 UI 与文件增强 | 正式交互消息持久化；真实文档修改/转换；版本与能力声明 | 文件数据图表/交互筛选后继续分析；选定 Word/Excel/PDF 操作按真实样例验收 |
| R5 Skills 完善与收尾 | Flutter 技能入口、社区样例与依赖状态、备份恢复入口、体验/真机交付 | 纯说明/资料/文件工具型技能分别验证；脚本型明确支持范围；P0 回归闭环 |

关键验收应使用真实业务行为，不仅检查页面存在：

1. 通用问答不强制出诊断题，数学教学能由明确请求/可选技能进入。

3. 历史分页、重命名/删除、分支、模型切换与文件附件可用；富文本用语义与原文断言验证。
4. 智能界面本地操作、提交续聊、重开恢复、切分支和旧 surface 操作拒绝。

6. 服务任务真实范围、原页来源、取消与恢复、成果保存重读、分享可读，成功必须有真实产物。
