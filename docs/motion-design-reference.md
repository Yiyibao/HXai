## 1. 专项目标与产品范围

让学习者看清 Agent 正在做什么、何时需要自己、哪些内容已经真正保存，同时建立安静、可靠的陪伴感。以教学内容的阅读和操作为第一优先级。

沿用已确认路线：华为 Mate 50 / HarmonyOS 4.2.0、Android APK、RikkaHub 固定基线、Kotlin / Jetpack Compose；手机独立联网，面向一至两名学习者。核心闭环为教学聊天 → 材料理解 → 有来源的自动记忆 → 真实学习成果。MathStudy 管正式计划、日历、错题和掌握度；本应用不因视觉设计增加这些模块。

本专项先覆盖应用内部页面、状态反馈和一个原创小伙伴。桌面悬浮宠物、系统顶部岛、锁屏常驻、手机自动化、多 Agent 调度面板、音乐、服饰商城和大量音效不进入 v1。本轮只交付方案与提示词；用户在网页端手动生成图片，图片只是视觉参考。

## 3. 原创视觉方向

### 3.1 原创小伙伴

工作代号 **“页芽”**，仅作讨论标识，名称和形象尚未定稿。外形是一枚站立的折页书签：偏长的纸片轮廓，一侧有不对称折角，中央细折痕，底部浅 V 形书签缺口；两枚小墨点眼睛，微小侧页可表达动作。主色浅玉绿，折角暖杏色。避免灰白圆角团子、球面投影大眼睛和 Coucou 的标志性动作。

正常页面伙伴约 32–40 dp；页面空态可用 64–80 dp；示意图放大只是为了看清形状。轮廓必须在小尺寸保持辨识度，动作仅围绕折页、侧页和视线的小变化。它不占据大型首页空间，不遮挡题图、公式、按钮、系统状态栏或键盘。

首版姿态：静候、专注阅读、组织讲解、等待核对、记录完成、成果完成、遇到问题、减少动画下的静态姿态。错误采用平静的低头或折页收拢，不哭泣、不责备学习者；用户答错时不使用失败表情。庆祝只表示系统操作完成。

### 3.2 视觉基础

以下是设计提案参数，需经页面稿和设备调试确认，不是冻结的实现常量。

| 项目 | 建议 |
|---|---|
| 风格 | 温暖的纸面阅读感、清楚的移动端层级、克制的原生 Material 3 结构 |
| 背景 / 卡片 / 分隔 | `#F7F8F3` / `#FFFFFF` / `#E3E9E3`；轻边线与极浅阴影 |
| 主色 / 正文 / 次正文 | 玉绿 `#2F6E60` / 墨色 `#202C29` / 灰绿 `#5D6963` |
| 等待 / 失败 | 暖杏 `#A96A24` / 暗红 `#A43C43`；同时显示图标与文字 |
| 排版 | 中文正文起点 16 sp、行高约 1.5；题面与公式按内容扩展；不把灰色说明做得过小 |
| 间距与形状 | 4 dp 网格，主页面横向留白约 20 dp；卡片圆角 16–20 dp，状态胶囊可更圆 |
| 交互目标 | 可点击区域至少 48 × 48 dp；图标视觉可小于触摸区域 |
| 示意画布 | 412 × 892 的逻辑比例；网页图可请求约 1080 × 2340，实际尺寸按工具支持选择 |

浅色稿先确定布局，随后验证深色模式。深色不是全局反相：背景、文字、材料预览和状态色独立调色，纸面 PDF 预览可保留白底。默认无声音，无持续震动；v1 不制作音效资产。触觉反馈仅考虑系统操作惯例，减少动画不影响信息可达性。

## 4. 信息架构与页面清单

主导航统一为 **聊天 / 材料 / 记忆 / 成果**。设置入口位于顶部菜单；历史会话由聊天页进入；Skills 放在设置次级入口和聊天的“教学方式”中。一个档案时弱化切换，两个档案时始终能看见当前归属；模型参数与协议调试留在设置。

| 页面 ID | 页面与重点 | 必须有的状态或操作 |
|---|---|---|
| P01 | 聊天空态：一个直接提问入口、拍题/选文件、近期会话 | 配置未完成时给“配置模型连接”，不假装可生成 |
| P02 | 教学聊天：题目、一次一个卡点、公式、来源、教学方式 | 生成中可停止；历史阅读不强制滚到底；继续提问与重新生成 |
| P03 | 材料列表与接收：文件类型、范围、解析状态 | 接收/待处理/处理中/部分完成/待核对/失败/取消 |
| P04 | 材料位置回看与符号核对：原图区域或 PDF 实际页 | 对不确定符号明确询问；提供选择或手动输入，保留原图 |
| P05 | 记忆列表：主题、来源类别、保存时间、状态 | 自动记忆开关入口、待核对与已保存分开、零条目空态 |
| P06 | 记忆详情：事实、证据等级、原聊天、修订操作 | 更正、删除和来源回看；冲突不冒充确定事实 |
| P07 | 成果列表：笔记/总结/练习、草稿与已导出区分 | 可进入预览；未成功导出时不展示文件成功标记 |
| P08 | 成果预览与导出：公式、来源、版本、格式 | 生成/校验/成功/失败；只展示已验证支持的格式 |
| P09 | 设置与首次配置：连接、档案、自动记忆、动效、备份、Skills | 密钥遮蔽；测试连接有真实结果；减少动画可关闭循环 |
| P10 | 错误与恢复状态板：取消、中断、429、记忆失败、分享取消 | 每种状态有下一步；样例内容标明为设计演示 |

P04/P06/P08/P10 可以使用子页面或底部面板，不要求新增主导航。页面图不是完整能力验收，P09 的模型、备份和格式是否可用以原方案和实际验证为准。

### 4.1 聊天的空间与阅读稳定性

顶部保留标题、当前归属入口和小伙伴；其下为固定最大高度的短状态胶囊。正在阅读材料时可展开过程摘要，显示真实文件及范围。底部是附件、输入框和发送/停止；生成中停止始终可见且可立即响应。

教学方式使用单个选择器，进入后选择引导学习、给我提示、检查步骤、完整讲解，不常驻四个大按钮。首屏以可读题目和讲解为主，伙伴不重复出现在每条消息。公式不逐字弹跳，流式更新不重播历史消息入场，不因表情改变挤动正文。

键盘出现时缩减装饰，保留输入与停止；底部导航可收起但不能遮挡输入。系统栏、屏幕缺口、手势区域按实际 insets 布局，不模仿 iPhone 的黑色灵动岛。200% 字体下以换行/滚动保证关键操作可达。

## 5. 真实状态到视觉的映射

### 5.1 聊天状态

沿用已有运行状态，不另建由时间自动推进的业务状态。

| 真实状态 | 对用户的短文案 | 伙伴及界面表现 |
|---|---|---|
| IDLE | 可以继续提问 | 静候；偶发折页微动，阅读时停用 |
| PREPARING | 正在整理上下文 | 小折角轻收拢；没有数值进度 |
| GENERATING | 正在生成讲解 | 专注姿态；小状态点轻变，不动画化公式正文 |
| TOOL_RUNNING | 阅读材料 / 查找相关记忆 / 生成笔记 | 文案由真实工具类型映射；未知工具显示“正在处理” |
| WAITING_USER | 请核对这个符号 / 需要你确认 | 卡片一次展开，随后静止，问题与按钮一直存在 |
| COMPLETED | 本轮回答完成 | 胶囊恢复安静；可一次舒展，不写“解答已验证” |
| FAILED | 请求失败，内容已保留 | 稳定错误卡；可重试/调整连接，无持续抖动 |
| INTERRUPTED | 连接中断，已保留收到的内容 | 静态暂停姿态；继续或重新生成依据能力提供 |
| CANCELLED | 已停止 | 立即停循环，保留现有正文；不自动重试 |

429 和重试等待是错误/重试原因的展示，不凭空修改数据合同枚举。只有运行层确实安排了重试，才显示真实可取消的等待时间；没有调度时间时只说“等待重试”。不展示虚构 token、成本、剩余秒数或完成百分比。

### 5.2 持久化 Job 与结果语义

沿用合同中 MEMORY_EXTRACT、MEMORY_SUMMARIZE、MATERIAL_PARSE、ARTIFACT_EXPORT 及 PENDING / RUNNING / RETRY_WAIT / SUCCEEDED / FAILED / CANCELLED。下面的“接收、核对、部分完成、校验”等是 UI 展示阶段或结果属性，实施时据已存在数据推导；若需要持久化新字段，先明确修订合同，不能默默增加状态枚举。

| 场景 | 成功反馈依据 | 非成功反馈 |
|---|---|---|
| 明确/自动记忆 | 来源检查、去重和数据库事务成功；显示实际新增/更新条数 | 零候选不庆祝；待核对、冲突、旧来源被丢弃各用准确文案 |
| 材料接收 | 原文件确实进入本地仓储 | 文件选择取消无失败动画；复制失败不开始解析 |
| 材料解析 | 保存解析版本、块和实际范围 | 指定页/部分解析明确范围；模糊符号仍待核对；DOCX 用段落/表格锚点 |
| 成果草稿 | artifact revision 真正保存 | 只说“草稿已保存”，不说 PDF 已生成 |
| 导出文件 | 临时写入、结构检查、文件及版本原子登记完成 | 校验失败/存储不足不显示可打开的成功文件 |
| 外部分享 | 系统分享面板被用户调用 | 仅能确认“已打开分享”；取消不撤销本地导出，不声称接收方已收到 |

### 5.3 并发、迟到与恢复

主状态优先级：当前会话 WAITING_USER / 错误 → 当前聊天运行 → 用户显式启动且当前可见的材料/成果任务 → 记忆后台任务 → 静候。其他任务在对应页面和次级状态中继续显示；不因记忆整理把“生成讲解”替换成“记住了”。

每个瞬时事件携带所属档案、任务 ID、会话/成果版本及唯一事件键。只有当前所属和版本匹配才驱动主伙伴；终态后的迟到事件不把状态倒退。消息列表重组、转屏、重新进入页面和进程恢复都不重播成功动作。状态文本可恢复，庆祝事件只消费一次；恢复状态展示不能再次执行导出或记忆写入。

切换档案后立即展示新档案的状态；旧档案任务可继续按原归属完成，但不会在新档案弹出内容、数量、来源或伙伴反馈。页面离开、后台、锁屏时停止装饰帧循环；回前台重新读取真实状态，而不是续播过期动画。

## 6. 动效目录与初始参数

参数是调试起点；真实完成事件决定业务终态。动画时长不能变成操作最短等待，也不能拦截输入、取消、滚动或导航。跳过动画直接到正确终态必须可行。

| ID | 动效 | 初始建议 | 触发及打断规则 |
|---|---|---|---|
| FX01 | 状态胶囊切换 | 140–180 ms 淡变；图标最多 2 dp 位移 | 同一布局槽，状态快变可合并展示但不吞等待/错误/终态 |
| FX02 | 展开核对/过程卡 | 220–280 ms 尺寸和透明度变化 | 温和弹性，按钮随布局稳定可点；等待卡不能自动折叠 |
| FX03 | 新消息出现 | 首次插入 100–140 ms 淡入 | 不作用于每个流式片段、历史恢复或公式内部 |
| FX04 | 接收文件 | 240–320 ms 缩略图过渡到材料卡 | 使用选择后的文件锚点，不从屏幕外飞入；取消立即结束 |
| FX05 | 待机折页/眨眼 | 6–10 s 间隔，动作 120–220 ms，幅度 ≤1.5 dp | 非连续 60 fps 空转；输入、滚动、长文阅读时静止 |
| FX06 | 专注处理 | 约 2 s 的小状态点变化，折页幅度 ≤2 dp | 无百分比时不做进度条；减少动画时静态图标+文案 |
| FX07 | 已保存记忆 | 240–360 ms 一次折角舒展 | 实际提交事件；“已新增 1 条学习记忆 · 查看”保留静态入口 |
| FX08 | 成果导出完成 | 280–420 ms 一次轻抬，位移 ≤4 dp | 真实文件登记后触发；不得先庆祝后等待写盘 |
| FX09 | 来源回看 | 180–240 ms 内容淡变或轻移 | 找不到有效来源时给解释，不伪造跳转；无共享元素也可实现 |
| FX10 | 失败、取消和减少动画 | 静态图标；最多 100 ms 淡变 | 无惊吓、闪烁、全屏红色或循环抖动 |

可考虑弹簧起点：dampingRatio 约 0.85–1.0、stiffness 约 450–650；只用于小伙伴或卡片短过渡，不用于正文、数学符号或大页面摇晃。最终数值由 Compose 基线及设备实际效果决定。

低干扰提示可短暂显示，但“查看记忆”“打开文件”等功能在对应列表始终可找回；读屏或延长提示时长设置不能让操作丢失。动画关闭时全部状态与操作保留，不用“静态成功图”替代真实成功条件。

## 7. Kotlin / Compose 接入建议

沿用原生 UI 和现有消息/附件/公式组件，按页面增量修改。Canvas 绘制原创纸片轮廓和少量折页/视线参数；界面过渡优先用 Compose 现有动画 API，不新增 WebView、Rive、Lottie 或独立游戏循环作为 v1 前置依赖。[Compose 动画概述](https://developer.android.com/develop/ui/compose/animation/introduction)、[常见动画选择](https://developer.android.com/develop/ui/compose/animation/quick-guide)

拟议接口为 CompanionVisualState、StudyStatusPresenter、MotionPolicy、OneShotFeedback；均为规划命名，不宣称现有源码已有。运行层输出事实，Presenter 映射短文案，MotionPolicy 合并系统动画缩放设置、应用“减少动画”及前后台可见性。伙伴仅持有绘制参数，不接管网络、数据库、工具调用或任务推进。

AnimatedVisibility 用于卡片展开；updateTransition/animate*AsState 用于有限状态属性；Animatable 可编排可取消的短动作。形状应提前缓存，尽量把逐帧变化限定在绘制/变换，避免聊天列表和公式区域跟着每帧重组。已有 API 可用性在固定基线中确认；实验性共享元素 API 不是专项依赖。

系统关闭动画或应用减少动画时，所有循环和弹跳停用，状态立即更新；后台和不在屏幕上的伙伴不运行。读屏只播报有意义的状态变化，不朗读逐帧参数、打字闪点和每个流式 token。装饰角色不重复承担按钮语义，真实状态在文字区域提供。[Compose 无障碍指南](https://developer.android.com/develop/ui/compose/accessibility)

## 8. 分阶段安排与工作量

| 阶段 | 专项交付 | 与原计划关系 |
|---|---|---|
| 当前设计准备 / S0 | 文档、页面提示词、原创方向、状态映射、视觉验收表 | 不新增业务门禁，不推迟或冒充真机/API验证 |
| S1 | 静态页面骨架、四主入口、聊天状态胶囊、键盘/公式布局、失败与取消 | 静态操作先通过，再加 FX01–FX03；原创伙伴可先静态 |
| S2-A / S2-B | 记忆列表和证据详情、真实提交反馈、并发与档案隔离 | FX07 接事务成功；不添加正式掌握度或新抽取算法 |
| S3 | 材料接收、指定页解析、原图核对、来源定位 | FX04/FX09 连接真实范围与来源，保留全部失败路径 |
| S4 | 草稿预览、导出状态、真实文件打开与分享 | FX08 以文件登记为条件；DOCX 仍是原方案条件项 |
| S5 / S6 | 减少动画、后台退出、恢复与事件去重、深色与大字、真机性能 | 状态真实性和可达性必过；装饰可降级静态 |

视觉稿由用户手动生成并选择，缺少定稿时可以继续功能和静态界面工作，不把图片生成当成新的 S0 必需项。建议先生成 P02/P03/P05/P08 检查同一风格，再补空态、详情、设置和状态板。

工程增量暂估 **4–7 个净工作日**：公共视觉组件与状态反馈 1–2，原创伙伴 1–2，页面细节和真机调试 2–3。四主入口、功能页和错误处理已有工作属于原计划，不重复计费。该增量是规划假设，依赖固定基线可构建、用户选择视觉方向及实际设备测试；复杂角色、音效、悬浮和大幅页面重构不含在内。

原实现估算 31–55 日，对应暂估总量 **35–62 日**；若首版加入 DOCX，原 34–61 日对应 **38–68 日**。不是交期承诺，S0 完成后再校正。

## 9. 专项验收与降级

详细条目纳入 [验收矩阵](acceptance-matrix.md) 的 UX01–UX12，动作编号另用 FX01–FX10。关键检查包括：真实终态、并发归属、动画可打断、公式和键盘布局、减少动画、读屏、后台暂停、恢复去重、实际范围和文件状态。

性能目标以 Mate 50 发布构建的可复现场景比较“动效开/关”：同一内容、字体、设备刷新率和构建，预热后分别连续 5 分钟流式+公式阅读+列表滚动；记录帧时间分布、超帧预算比例、内存及温度情况。暂定目标：开启动效导致超帧预算比例增加不超过 2 个百分点，帧时间 P95 增加不超过 10%；这些是待实测调整的目标，不能宣称已达到 60 fps。若超标先关闭循环、减少绘制，再保留静态角色和必要状态过渡。

静态图验收：10 个页面/状态稿共用角色、色板、导航与字号层级；中文和公式需人工核对；大字、键盘、错误、深色需专门检查。图中的数量、来源、版本、文件大小是示例，不是运行证据。动效节奏、打断、性能及可访问性只能在交互原型/实现和真机上验收。

## 10. 页面稿接续规则

用户在网页生成后，优先记录：页面 ID、选用版本、需保留元素、需修正元素。生成图连同提示词保存为视觉参考，实施时用 Compose 重建控件与文字，不将整张截图贴入应用。角色再按原创轮廓绘制为代码/矢量，图像模型给出的“矢量感”图片不是可直接编辑的矢量文件。

每次改稿优先维持布局和角色一致性，中文乱码、公式错误、伪造能力、按钮遗漏先修正。单纯漂亮的成功页面不能替代失败/等待/恢复稿，也不能证明记忆写入、材料解析或导出已成功。
