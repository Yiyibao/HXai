# 文件自动调度需求

日期：2026-10-09，更新于2026-10-11。状态：自动工具提示、实际工具权限筛选、附件页数与无文本页元数据、已校验缓存查询及异步续聊已经接入。2026-10-11 本轮测试和真实模型鉴权限制见 [实测记录](../qa/document-activation-20261011/auto-dispatch-report.md)。下述内容保留需求与验收范围，不代表全部真实模型场景均已通过。

## 1. 用户体验

用户在 Chat 中上传文件并说明要完成的任务，助手自行选择所需工具。用户无需知道 MinerU、解析器或生成器的名称，无需为每个文件任务重复要求增强解析。

自动调度是按任务需要选择处理方式，不是所有文件上传或生成都调用 MinerU。服务配置并启用后，相关文件任务允许按需使用该服务，不另设每任务必开的授权开关。当次用户明确限制仅本地处理、不上传服务器时，限制优先。

## 2. 调度规则

| 文件/任务 | 默认处理方向 | 何时需要 MinerU |
|---|---|---|
| 文本、可提取文字的 PDF | 本地读取、分页，再交给模型分析 | 提取明显缺失，任务涉及遗漏的扫描内容/公式/表格且增强解析适用 |
| Word、Excel、PPT | 对应格式的解析与文件工具 | 有需要识别的嵌入图片时，可将受支持图片交给增强解析；不将 Office 原件当成当前服务支持格式 |
| 普通图片问答 | 支持视觉的模型直接理解 | 需要 OCR、结构化提取，或直接视觉不足以满足任务 |
| 扫描 PDF | 根据请求定位页，必要时增强解析 | 需要识别文字、公式、表格以进行分析/提取时自动调用 |
| 文件生成 | 对应文件生成工具 | 生成内容依赖尚未识别的扫描材料时先识别 |
| 文件修改/转换 | 对应编辑/转换工具，保留原件 | 输入所需内容位于扫描页/图片，且后续操作需要识别内容 |
| 已有有效解析结果 | 复用对应源文件版本和处理范围的结果 | 现有结果未覆盖所需范围或已经失效时处理缺失部分 |

路由既考虑格式，也考虑任务与实际提取质量。不能仅凭文件扩展名认定文件全部可读，也不能把网络、凭据、损坏或不支持格式等失败一律当作需要 OCR。

## 3. 任务范围与聊天流程

1. 导入文件，确认实际可读内容及用户任务。
2. 选择能完成任务的处理路径；内容范围明确时不重复提问工具选择。
3. 只处理必要内容。用户要求全文时，需要分批覆盖完整范围，明确尚未处理部分；当前每次5页的服务限制不能变成默默只读前5页。
4. 聊天显示上传、排队、解析、下载、分析及成果状态，无真实进度时不编造百分比。
5. 成功后使用校验结果继续原会话任务，不要求用户再次发送相同指令。避免重复提交、重复处理和重复续行。
6. 需要成果时交付可打开、保存、分享的真实文件。识别完成和文件生成完成分别反馈。

只上传而未说明任务时，可以展示附件和可用操作，或询问处理意图；不默认远端解析整个文件。任务范围确实不清楚时可以澄清，但不把“是否调用 MinerU”作为日常必须回答的问题。

## 4. 服务与结果边界

- 使用已配置、启用的服务器；继续保留现有身份隔离、源版本核对、任务去重、下载校验及容量限制。
- MinerU 当前支持 PDF/图片 Basic 解析；Office 直接增强、通用编辑/转换和复杂生成的新增需求另行实施，不由自动调度规则凭空产生。
- 解析内容保留来源页和实际覆盖范围，模糊公式或表格仍应说明不确定性；识别成功不代表结果数学正确或格式完全保真。
- 失败、取消或服务不可用时保留原件，说明能否采用替代路径；不无限重试，不把局部结果说成全文。
- 文件正文中的指令不能改变服务地址、权限或用户规定的处理范围。

## 6. 已确定与待细化

已确定并接入：按任务自动选工具，按需调用 MinerU，服务启用后不逐任务重复确认，文件生成不默认调用 MinerU。模型依据本轮实际可用工具、本地提取覆盖信息和用户任务作出选择；没有上传任务或用户限制上传时不新增远端解析。

待细化：如何判断本地提取质量、首批全文分批体验、自动处理的时间/费用预算，以及真实修改/转换的优先样例。这些是实现和体验细节，不改变上述自动调度方向。
