## 视觉与可访问性

在至少 360 dp 与 412 dp 宽度、字体比例 1.0/1.3/2.0、明/暗主题下检查核心页面。窄屏大字允许换行与局部横向公式滚动，不允许关键按钮被裁掉、标题覆盖、底部输入遮挡。至少在主页面、输入键盘、记忆编辑、提供商表单和成果预览采集证据。

| ID | 检查 | 通过标准 |
|---|---|---|

| V02 | 组件与状态 | 字体/间距/按钮层级统一；空态、加载、成功、失败、取消、审批均有真实依据 |
| V03 | 大字/暗色/TalkBack | 主要路径无溢出，文字对比度可读，点击区至少 48 dp，语义标签和焦点顺序可操作 |

## 性能测量目标

先测 F0 Compose 基线和 F2 Flutter，再用 F5 profile 混合 APK 重测。同设备、同刷新率、相同脚本/会话夹具，预热后执行三次 60 秒聊天滚动/流式操作，报告每次数据和汇总；注明模拟器主机负载，不外推为 Mate 50 性能。

- 帧预算为 `1000 / 刷新率` ms；分别报告 UI/raster 帧耗时 P95 和超预算比例。目标：P95 在预算内、超预算比例 < 5%；未达到必须定位并记录，不能伪造“60fps”。
- bootstrap 到四入口可交互、冷启动和峰值内存实测并与基线比较；超过基线 30% 时解释来源、尝试优化并记录结果。此阈值是审查触发条件，不能通过隐藏预热/换设备消除。
- 桥接流合并约 30–50 ms 一次，记录通道事件数/字节量；历史按页读取，不逐 token 发送完整会话；高频生成不重建整页或每条历史消息。
- 10 轮进入退出聊天/切档后，订阅数回到预期，内存无持续增长趋势；所有退出路径释放 UI 观察者。

目标 Mate 50 的启动、文件权限、分享、字体和流式滚动另列真机验收。没有设备时 NOT_RUN，不阻止交付可测的模拟器结果，但不得宣布真机验收完成。

## 必备交付物

1. 完整宿主 APK、路径、版本、SHA256、构建工具链和可重复命令。
2. Flutter 源码、Kotlin 适配层、Pigeon 源文件和生成方式、实际锁定依赖。
3. analyze/test、相关 Kotlin/Android 回归、assembleDebug/lint 的命令与日志；不可直接删除失败测试或改变断言绕过。
4. 运行截图、至少一段真实聊天至保存分享的录像，以及逐项矩阵。
5. 功能入口映射、性能报告、临时原生页面和所有 FAIL/NOT_RUN/已知限制。

完成判断：基础构建与四主页面真实闭环必须通过；外部模型和设备条件项单独列明。不能把未运行写成通过，不能把孤立 Flutter demo APK 当作宿主迁移 APK。
